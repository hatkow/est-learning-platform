# AIO記事テンプレート

AI回答エンジン（AI Overviews / ChatGPT検索 / Perplexity）に**引用される**ための記事骨格。
ルールの根拠は [docs/blog-style-guide.md](../../../../docs/blog-style-guide.md) の「AIO（AI回答エンジン対策）」章。
`node scripts/lint-blog-draft.mjs` がこの構造を機械的に検査する。

## 骨格

```markdown
---
title: "（検索クエリを含む。60字以内）"
slug: english-hyphenated-slug
description: "（80〜120字。記事の結論を含める）"
date: 2026-08-19
category: 生成AI活用
tags: [タグ1, タグ2, タグ3]
author: EST編集部
coverColor: "#1a56a0"
---

（★リード：100字以内。検索意図への直接回答を断定形で。前置き・背景説明から入らない。
　AIが最優先で抜き出す位置なので、ここだけ切り出されても答えとして成立させる）

## 本記事で解決できるお悩み

- （読者の検索意図を2〜4個）

### （★H3＝1つの質問に対応する主題。見出しだけで何に答えるか分かること）

（★第一段落＝50〜140字の回答パッセージ。結論を先に置く。
　「これは」「その理由は」など指示語で始めない。主語を毎回明示する）

（2段落目以降で理由・詳細・具体例。一文は100字以内）

### （同上を7〜10セクション）

### まとめ

（★2026年8月時点の情報です、のような時点表記をどこかに入れる）

## よくある質問

（★「まとめ」の後、記事の最後に置く。前に置くと質問見出しが本文の見出しと入れ子になる）

### （★質問文をそのまま見出しに）

（★回答。30〜200字。質問だけ読んでも成立する独立した回答）

### （設問2）

（回答）

### （設問3）

（回答）
```

## 必ず守る5点

| # | ルール | 検査 |
| --- | --- | --- |
| 1 | リードは100字以内・断定形・前置きなし | `[AIO] リード文が…` |
| 2 | 各見出し直下の第一段落は50〜140字、指示語で始めない | `[AIO] 見出し直下の第一段落が…` / `第一段落が指示語…` |
| 3 | よくある質問を3〜5問（回答30〜200字） | `[AIO] よくある質問が…` |
| 4 | 「2026年8月時点」のような時点表記を入れる | `[AIO] 時点表記がありません` |
| 5 | 単位付きの具体的な数値を入れる（**架空の数字は禁止**） | `[AIO] 単位付きの具体的な数値が…` |

## FAQの2形式

見出し形式（推奨）と Q/A形式のどちらでもよい。どちらも `extractFaq()`（[lib/blog.ts](../../../../lib/blog.ts)）が拾い、`FAQPage` 構造化データになる。

```markdown
## よくある質問

### 承認フローは無料ライセンスでも作れますか？

作れます。Microsoft 365の標準ライセンスに含まれる範囲で構築できます。ただし……
```

```markdown
### よくある質問（FAQ）

**Q. 承認フローは無料ライセンスでも作れますか？**
A. 作れます。Microsoft 365の標準ライセンスに含まれる範囲で構築できます。ただし……
```

セクション見出しに「よくある質問」または「FAQ」を含めること（これが検出の起点）。

## やってはいけない書き方（AIに拾われない）

| NG | なぜ |
| --- | --- |
| 「近年、生成AIの活用が進んでいます。」で始まる | 前置きから入るとリードが回答にならない |
| 「これには2つの理由があります。」で段落を始める | 切り出されると何の話か分からない |
| 「〜であり、〜のため、〜という点においては〜」と続く長い複文 | AIが一節として抽出できない |
| 「約30%の工数削減が可能です」（根拠なし） | 架空の数字。実データか公的出典が無いなら書かない |
| FAQを本文の要約で埋める | 周辺の疑問を拾わないと引用価値が出ない |
