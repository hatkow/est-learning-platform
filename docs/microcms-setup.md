# microCMS 導入手順（コラム機能）

このサイトのコラム（`/blog`）を **microCMS の管理画面から執筆・投稿**できるようにする手順です。
クライアントを招待して複数人で運用することもできます。

> 実装はフォールバック方式です。**環境変数を設定するまでは今まで通り Markdown ファイルで動作**し、
> 設定した瞬間に microCMS へ切り替わります。焦らず進めて大丈夫です。

---

## STEP 1. microCMS に登録

1. https://microcms.io/ にアクセスして無料登録
2. 「サービス」を新規作成（例: サービスID `est-learning`）
   - サービスIDが `https://est-learning.microcms.io` の `est-learning` 部分になります（後で使います）

## STEP 2. ブログAPIを作成

1. サービス管理画面で「APIを作成」→「**自分で決める**」
2. **API名**: `ブログ` / **エンドポイント**: `blog`（← この名前を使います）
3. **APIの型**: 「**リスト形式**」を選択

## STEP 3. APIスキーマ（項目）を設定

以下の項目を追加してください（フィールドIDは**この通りの英字**にしてください。コードが参照します）。

| フィールドID | 表示名 | 種類 | 必須 | 備考 |
|---|---|---|---|---|
| `title` | タイトル | テキストフィールド | ✓ | 記事タイトル |
| `slug` | スラッグ | テキストフィールド | ✓ | URLに使う英数字（例: `powerapps-tips`）。記事ごとに一意に |
| `description` | 説明 | テキストエリア | ✓ | 一覧・検索・SNSに出る要約（80〜120字目安） |
| `content` | 本文 | リッチエディタ | ✓ | 記事本文。見出し・リスト・表・画像が使えます |
| `eyecatch` | アイキャッチ | 画像 | | 記事のカバー画像（無くてもOK。無ければ青の背景） |
| `category` | カテゴリ | テキストフィールド | | 例: `Power Platform入門`（※下の補足も参照） |
| `tags` | タグ | テキストフィールド / 複数 | | 例: `PowerApps` `業務改善` |
| `author` | 著者 | テキストフィールド | | 例: `EST編集部`。空なら自動で `EST編集部` |
| `date` | 公開日 | 日時 | | 並び順に使用。未設定なら公開日時を使用 |
| `coverColor` | カバー色 | テキストフィールド | | 任意。画像が無いとき背景色に（例: `#1a56a0`） |

> **補足（カテゴリ・タグ）**: シンプルに始めるなら上記の「テキストフィールド」でOKです。
> 将来きちんと管理したい場合は、別途「カテゴリ」APIを作って参照型にもできます（その場合はご相談ください。コードを微調整します）。

## STEP 4. APIキーを取得

1. サービス管理画面 →「サービス設定」→「**APIキー**」
2. キー文字列をコピー（STEP 6 で使います）

必要な権限は、何をするかで変わります。

| やること | 必要な権限 | 使うもの |
|---|---|---|
| コラムをサイトに表示する | **GET** | `lib/blog.ts` |
| 生成した記事を下書きとして登録する | **GET** ＋ **POST** | ダッシュボードの「microCMSへアップ」 |
| 下書きを一般公開する | 上記＋**マネジメントAPI**の「コンテンツの公開状態を変更」 | `npm run approve-blog-draft` |

> **マネジメントAPIの権限は別タブにあります。** 「APIキー」の編集画面で
> 「マネジメントAPI」タブに切り替え、「コンテンツの公開状態を変更」を有効にしてください。
> 通常のコンテンツAPI権限だけでは、公開しようとすると 401/403 で止まります。

表示だけなら GET だけで足ります。記事の自動生成・入稿まで使う場合は POST も有効にしてください。

## STEP 5. テスト記事を1本作る

1. `blog` API で「追加」→ 各項目を入力
   - `slug` は必ず入れてください（例: `hello-microcms`）
2. 「公開」ボタンを押す

## STEP 6. 環境変数を設定（サイトに接続）

### Vercel（本番）の場合
Vercel のプロジェクト → **Settings → Environment Variables** に以下を追加:

| Name | Value |
|---|---|
| `MICROCMS_SERVICE_DOMAIN` | STEP1のサービスID（例: `est-learning`） |
| `MICROCMS_API_KEY` | STEP4でコピーしたAPIキー |
| `MICROCMS_BLOG_ENDPOINT` | `blog` |

追加したら **Redeploy**（再デプロイ）してください。反映後、`/blog` が microCMS の記事に切り替わります。

### 設定後の確認

環境変数を設定したら、記事をアップする前に接続とスキーマを確認できます。

```
npm run check-microcms
```

接続の可否・登録件数・フィールドIDの一致を出します。ここが通らないうちに
記事を生成しても、最後の登録で失敗します。

### ローカルで試す場合
プロジェクト直下に `.env.local` を作成:

```
MICROCMS_SERVICE_DOMAIN=est-learning
MICROCMS_API_KEY=あなたのAPIキー
MICROCMS_BLOG_ENDPOINT=blog
```

`npm run dev` で確認できます。

## クライアントを招待して執筆してもらうには

- microCMS 管理画面 → 「メンバー管理」からメールで招待
- 権限（ロール）で「執筆はできるが公開はできない（下書きまで）」等を設定可能
  - 例: クライアント＝下書き作成 → 御社＝確認して公開
- ※ メンバー追加・権限管理は **有料プラン**が必要な場合があります（登録時にプランをご確認ください）

## 記事公開後、すぐにサイトへ反映したい場合

標準でもアクセス時に最新を取得しますが、より確実にするには microCMS の
「API設定 → Webhook」から Vercel の Deploy Hook を呼ぶと、公開のたびに自動再デプロイできます。
必要になったら設定をお手伝いします。

---

## 困ったら

- 記事が表示されない → 環境変数のスペル、`slug` の有無、記事が「公開」状態かを確認
- 画像が出ない → `eyecatch` に画像を設定しているか確認
- それでも解決しない場合は、この手順のどこで詰まったか教えてください。
